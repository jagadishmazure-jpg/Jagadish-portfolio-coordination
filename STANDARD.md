# Portfolio repo standard

Apply to every new repo and every change to an existing one. A repo is not "done" until every gate below passes.

## 1. Coordinate before touching shared repos
- If another assistant may be working on the same account, check recent pushes (`gh api repos/<owner>/<repo> --jq .pushed_at`) and message it before editing a repo it touched in the last hour. One writer per repo at a time.
- Always `git pull` before editing. Never force-push or rewrite history without the user's explicit yes; back up with a mirror clone first.
- Commit with the account's GitHub noreply email, never a personal email.

## 2. Content rules (non-negotiable)
- **Fictional companies only.** No real company, client, vendor-as-client, merchant, or employer names in code, data, tests, docs, or commit messages. Use generic domain descriptions ("a food-ingredients manufacturer") or invented brands. Real tech vendors may be named only as technology used (Azure, LangGraph) or as a credited source.
- **Never commit copyrighted source material** (PDFs, ebooks, whitepapers, analyst reports, paid guides). Paraphrase in your own words, credit by name only, no direct quotes, and run an 8-word overlap check against the source text (target 0 hits).
- **Real numbers only.** Every figure in a README comes from an actual run in the repo. Simulated or synthetic results are labelled as such. State sample sizes; small self-written test sets are "regression checks", not quality claims.
- **Honest status.** A Built / Written-not-run / Planned table. Never claim deployment, PyPI releases, or badges for workflows that do not exist.

## 3. Engineering gates
- CI (GitHub Actions, actions pinned to full SHAs, pinned tool versions): install deps including pytest, lint (ruff), tests, a docs check that README numbers and test counts are regenerated from a real run, gitleaks over full history, and a brand-name check whose blocklist is stored as hashes (never plain names).
- Test counts must be generated by a script that actually prints the total (avoid `-qq` swallowing it).
- CodeQL, Dependabot (alerts + security updates; do not auto-merge major bumps), secret scanning + push protection, private vulnerability reporting.
- LICENSE (MIT unless otherwise chosen), SECURITY.md, repo description and topics.
- Two `main` rulesets: no force-push or deletion; required CI checks on PRs (admin bypass allowed).
- IaC where cloud is involved: Terraform + Bicep parity, `terraform validate`/tflint/checkov and `bicep build` in CI, deploy workflows gated off by default. Never create billable cloud resources without showing the resource list and cost estimate and getting the user's yes.
- Stay on free tiers (public repos, no paid GitHub features).

## 4. Documentation (mandatory, for the owner, recruiters, and adopters)
README plus `docs/` must cover:
1. Recruiter summary (3-5 lines: problem, approach, proof numbers)
2. Purpose and who it is for
3. Architecture (mermaid diagram)
4. How it works, step by step
5. Real code excerpts and their real output
6. How to run (offline first, then optional cloud)
7. Guardrails and security controls
8. Limitations and known failures (keep known misses visible as tests)
9. Built vs planned table
10. `docs/implementation-guide.md` for adopters
11. `docs/interview-points.md`
12. Threat model (STRIDE / OWASP LLM Top 10 where relevant) and ADRs for key decisions
13. Related repos (cross-link overlaps instead of duplicating)

## 5. Topic best practices to apply where relevant
- **Agents:** least-privilege tools, human approval before risky actions, input/output guards, prompt-injection tests, tracing with PII masking, eval gate in CI with safety metrics required at 1.0.
- **Structured output:** one schema source (Pydantic / JSON Schema), provider-native constrained decoding when available, reject extra keys and NaN, 1-2 repair retries then escalate, log repair and escalation rates, never echo raw row data in errors.
- **LLM-as-judge:** probe position, length and self-preference bias in both orders; exclude ties from denominators; report order-flip rate; calibrate against human labels (Cohen's kappa); use reference-guided rubrics; confidence intervals (Wilson) and enough cases to resolve the threshold; monitor judge drift.
- **Model routing:** realistic cost for local models (amortised infra), retries with backoff, circuit breakers, rate-limit handling, eval-informed routing, prices with an as-of date, real model cards (intended use, limitations, eval results, NIST AI RMF / EU AI Act transparency).
- **Privacy:** keyed HMAC pseudonymisation (key from env, rotation documented), checksum validators for PII detection.
- **Data:** contracts, lineage, medallion layers, metrics layer; vendor-neutral framing.

## 6. Before declaring done
- Fresh clone, run tests, confirm CI and CodeQL green on the latest commit.
- Brand check and overlap check pass.
- Update the profile README table and total from real counts, and verify the table sums to the total.
- Report: repo link, real test count, CI status, built vs planned, and anything left open.
